## Problem Statement

The owner completes lines in the desktop LiveEditor with Cmd+Enter. After the completion is sent to the web dashboard, the owner still wants to see at a glance which tasks are done. So a finished line should stay in the editor with a strikethrough, and the owner removes it later with the Delete key. Cmd+Enter on such a line must do nothing. This behavior is switched on and off in Settings.

The owner's reference screenshot (2026-11-02) shows `- [x] 10月の請求書の提出` struck through above unfinished `- [ ]` lines. The owner called it "only an image" of the idea.

## What exists today (static read of `3cd1f47a`)

- **Keeping the line already exists.** When the Settings switch **"Clear finished lines"** is off, a finished line stays as `- [x] title` (`apps/web/src/components/electron/LiveEditorAppearance.tsx:255-271`). The switch defaults to off (`packages/desktop-contract/src/settings.ts:66`). The desktop main process reads it when it creates a completion (`apps/desktop/electron/offline/WorkspaceService.ts:521`).
- **Completed rows carry an identity.** On desktop, completing a row rewrites it to `- [x] …` and sets `row.completionId` (`WorkspaceService.ts:533-535`). That id survives restarts, and is dropped only when the row text changes (`WorkspaceService.ts:455`).
- **Cmd+Enter already skips rows the system recorded.** A row with a `completionId` is rejected in the renderer (`packages/live-editor/src/DurableEditorStore.ts:298`) and in main (`WorkspaceService.ts:482-488`).
- **A typed `- [x]` row can still be recorded.** A row the user typed as `- [x] …` has no `completionId`, so Cmd+Enter records it (`WorkspaceService.ts:490-495`).
- **Nothing marks kept rows visually.** The editor is a plain `<textarea>` (`packages/live-editor/src/SharedEditorSurface.tsx:266`), and a textarea cannot style individual lines.

## What Makes This Cool

The editor becomes a quiet receipt of the day. What you finished stays in view and reads as settled, and what remains is easy to pick out. Pressing Cmd+Enter on a finished line is safe, because it can never log the same task twice by accident.

## Constraints

- **Desktop editor only.** The bundled renderer (`apps/desktop/renderer/NativeEditor.tsx` → `SharedEditorSurface`) gets the change. The web LiveEditor is not modified; it is being deleted separately (#215).
- **Colors come from theme tokens only.** No hard-coded hue, and never amber. The default theme is stock shadcn Default (#213).
- **No disturbance to typing.** IME composition, selection, caret, voice input, and textarea keyboard handling must behave exactly as today. The owner writes Japanese through an IME and voice input.
- **No change to the offline write path.** Row identity, edit-range capture, and the durable store's command contract stay the same. The feature is renderer drawing plus two guards.
- **The line must stop at the text.** The strike covers only the title's glyphs and ends at its last visible character. It never stretches to the right edge of the editor, which reads as a bug (owner, 2026-11-02).

## Premises (agreed in D5; premise 3 revised by the owner's later direction)

1. **Keep mode is "Clear finished lines" off.** No second switch is added. The switch keeps its two states: on tucks finished lines away, and off keeps them in place, struck through. Only the description copy changes.
2. **In keep mode, every finished-checkbox row is struck, and Cmd+Enter on it does nothing.** A finished-checkbox row is any row that `parseCheckboxLine` reads as checked, including a `- [x]` the user typed. As a result, "type `- [x]` and press Cmd+Enter to record it" works only in clear mode.
3. **Desktop editor only.** Revised from "desktop and web" after the owner asked to delete the web editor (#215).
4. **Deleting a struck row is plain text editing.** The Completed record stays and remains visible on the dashboard. Turning `[x]` back into `[ ]` removes the strike, and Cmd+Enter can record the line again, since repeating a task is intended.
5. **The strike color is a theme token** (`--muted-foreground`), never a fixed hue.

## Approaches Considered

### Approach A: decoration overlay (chosen, D7)

A transparent layer over the textarea with identical text metrics draws only the strike line. Effort S (human ~1–2 days / CC ~30–45 min). The textarea is untouched.

### Approach B: full mirror rendering (rejected)

The textarea text is made transparent and a layer underneath renders all text, with finished rows dimmed and struck. Rejected because IME composition text can briefly disappear when the mirror lags.

### Approach C: replace the textarea with CodeMirror 6 (rejected)

Rejected because it rebuilds the offline write guarantees (row identity, edit ranges) from v0.25.0 to get one line style.

## Recommended Approach (A), with the approved visual

**Approved visual (D9, "ボードのC"):** a hairline strike in `--muted-foreground`, drawn over the title only. The `- [x] ` marker is not struck. Text keeps its normal color.

### Rendering

- **Where the overlay lives (eng review D1).** `SharedEditorSurface` owns the overlay, because it already owns the textarea's padding, border, font class, font size and line height. It gets one boolean prop, `strikeFinishedLines`. Desktop `NativeEditor` passes keep mode; the web surface passes nothing, so nothing changes there.
- **Where the overlay code lives.** The overlay component (`FinishedLineStrikes`) lives in `packages/live-editor/src/`, beside the surface. The textarea and the overlay read one shared metrics constant, so the two can never drift apart. The pure helper `splitFinishedLine(line)` lives in `liveEditorUtils.ts` beside `parseCheckboxLine` and reuses `CHECKBOX_LINE_REGEX`; no second regex is written.
- **Wrapper and Details (eng review D2).** The textarea moves into a `relative flex min-h-16 min-w-0 flex-1` wrapper on both hosts, so there is a single render path. The wrapper (not just the textarea) takes `hidden={details !== undefined}`. The textarea is never unmounted, which preserves its value, caret and IME state when Details opens.
- **Layer setup.**
  - The layer is absolutely positioned with `pointer-events: none` and `aria-hidden="true"`.
  - Its text is `color: transparent`, and it has no background, so the textarea's caret and selection stay visible.
- **Geometry (eng review D3).** The overlay is a fixed clip viewport that covers exactly the textarea's padding box:
  - It is offset by the textarea's border width.
  - Its size is the textarea's fractional border-box size minus the border, read from `getBoundingClientRect`. Rounded `clientWidth` / `clientHeight` would wrap a near-limit line one glyph later under page zoom. When the textarea shows a classic scrollbar, the overlay sets `scrollbar-gutter: stable` so layout reserves the same scrollbar width inside it; a gap of up to 1px between the integer offset/client sizes and a fractional border is rounding, not a scrollbar. A `ResizeObserver` on the textarea keeps the size current, and font or padding changes re-sync it.
  - It uses `overflow: hidden`.
  - Inside it, one content block carries the textarea's padding and is translated by `(-scrollLeft, -scrollTop)` on the textarea's `scroll` event and after every value change.
  - The content block's width is the viewport width, so the border and scrollbar are subtracted exactly once.
- **Metrics match the textarea exactly.** Both elements share the font family class, font size (`liveEditorFontSize`), line height (`LIVE_EDITOR_LINE_HEIGHT`), padding, `letter-spacing`, `tab-size`, `white-space: pre-wrap` and `overflow-wrap: break-word`.
- **Each row is rendered as three pieces:**
  1. The prefix (`- [x] `, taken from `parseCheckboxLine`'s title offset) as undecorated transparent text.
  2. The title with trailing whitespace removed, as a span with `text-decoration-line: line-through`, a 1px thickness, and `text-decoration-color: var(--muted-foreground)`.
  3. Any trailing whitespace, as undecorated transparent text.

  Consecutive unfinished rows collapse into one undecorated transparent run, and text after the last finished title is not mirrored, because later text never moves earlier glyphs. A note with no finished line mirrors no text. The viewport always covers the textarea's padding box; only the mirrored content's DOM size follows finished rows, not note length, because it ends at the last finished title.

- **Wrapped titles.** Because the strike is an inline text decoration, each wrapped fragment ends its line at that fragment's last glyph. No positioned or full-width rules are drawn.
- **Scroll sync.** The layer's content is translated by `-scrollTop` and `-scrollLeft`. The translation is updated on the textarea's `scroll` event, on value changes, and on resize.

### Where keep mode is read (no new plumbing)

- **One source of truth.** Keep mode is `liveEditorClearOnComplete === false` in the workspace snapshot that main pushes to the editor renderer: `snapshot.main.workspace.preferences.settings`.
- **The renderer store already reads it.** `DurableEditorStore` receives the snapshot via `host.subscribe` (`packages/live-editor/src/DurableEditorStore.ts:130`). It already reads this exact field for caret placement (`:353`).
- **The overlay reads the same field.** `NativeEditor` reads `workspace.preferences.settings` through `useSyncExternalStore` (`apps/desktop/renderer/NativeEditor.tsx:72`, `:162`), and passes keep mode to the overlay from there.
- **Live updates from the Settings window.**
  1. The Settings window sends a `preferences` command.
  2. `WorkspaceService` applies it and bumps the preferences revision (`apps/desktop/electron/offline/WorkspaceService.ts:931-945`).
  3. Main publishes the new snapshot.
  4. The editor re-renders. Strikes appear or disappear without a reload, and the next Cmd+Enter uses the new mode.
- **The store's contract stays the same.** No new IPC channel, field, or command is added. The guard reads a value the store already has, so the "no contract change" constraint holds.
- **Main checks its own copy.** It reads `state.preferences.settings`, the same object it already reads for `clearAfter` (`WorkspaceService.ts:499-527`), inside the same transaction.

### Behavior

- **Renderer guard.** `DurableEditorStore.completeAt` returns `false` without sending a command when keep mode is active (`liveEditorClearOnComplete === false` in the workspace settings) and the caret row is checked (`intent.kind === 'checked'`).
  - **Second check inside the queue (eng review D4).** The check runs again inside the queued task, after `saveThrough` and right before `send`, because the setting can change while a save is in flight.
- **Main guard (eng review D4).** `WorkspaceService.completeLine` throws a distinct reason, `finished-line`, in keep mode when the row text parses as a checked checkbox.
  - **Order.** It runs after the existing revision check and row lookup (`WorkspaceService.ts:475-488`), so revision conflicts keep their current handling.
  - **Silent in the renderer.** `DurableEditorStore` maps `finished-line` to a silent `false`. There is no `fail()`, no "Could not save writing" message and no saved-state change. Main stays the authority, and a change in mid-flight still ends as a silent no-op.
- **Cmd+Enter on a struck row is an intentional silent no-op.** No toast, no sound, no count change. The strike itself is the feedback that the line is already done (office-hours R2-1).
- **Clear mode is unchanged.** That includes recording a typed `- [x]` row and the delayed clear.
- **Undo still works.** Undo within the toast window restores the original text. The row is no longer `[x]`, so the strike disappears.
- **Switching modes (eng review D6, office-hours R2-1).** A completion made in clear mode keeps the `clearAfter` it was given when it was created (`WorkspaceService.ts:521-527`). Switching to keep mode inside that window of at most 5 s does not cancel the removal. Switching from keep to clear never removes existing `- [x]` rows after the fact: they stay in place, unstruck, until the user deletes them.

### Settings copy

The description under "Clear finished lines" (`LiveEditorAppearance.tsx:257-263`) changes to say that **on** tucks a finished line away after the undo moment, and **off** keeps finished lines in place until you delete them.

**The copy is version-neutral (eng review D5).** It does not promise the strike, so it stays true for an older installed app. That matters because auto-download is off and "Later" can postpone an update without limit (`AutoUpdater.ts`). The strike is the visible confirmation, not a promise in the copy. The page is served by Next.js `/settings` inside the Electron Settings window, so the copy change ships through Vercel.

### Edge cases to cover

| Case                                                            | Expected                                                                                   |
| --------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Long title that wraps                                           | Every wrapped fragment is struck and ends at its own last glyph                            |
| Trailing spaces after the title                                 | Not struck; the line ends at the last visible character                                    |
| Indented or nested `  - [x] …`                                  | Struck exactly when `parseCheckboxLine` reads it as checked                                |
| Font size change, window resize, page zoom, scrollbar appearing | Strike stays aligned (same CSS, sub-pixel padding-box width)                               |
| Scrolling a long note                                           | Strike scrolls with its text                                                               |
| IME composition on or next to a struck row                      | Composition text renders normally; no flicker; strike realigns after commit                |
| Category switch                                                 | Strike follows the newly loaded note                                                       |
| Clear mode on                                                   | No strike drawn; behavior as today                                                         |
| Cmd+Enter on a struck row                                       | No command, no toast, "kept today" count unchanged                                         |
| Delete or Backspace on a struck row                             | Row removed; the Completed record remains on the dashboard                                 |
| `[x]` changed to `[ ]`                                          | Strike removed; Cmd+Enter records it again                                                 |
| Details opened and closed                                       | Wrapper and overlay hidden with Details; textarea stays mounted; strike realigns on return |
| Setting switched while a save is in flight                      | Main answers `finished-line`; renderer stays silent (no "Could not save" message)          |
| Clear-mode completion, then switch to keep within its window    | Row is still removed at its `clearAfter` (≤ 5 s)                                           |
| Switch keep → clear with struck rows                            | Rows stay, unstruck; nothing is removed after the fact                                     |
| Title ending exactly at the wrap width                          | Strike and text wrap at the same character (border subtracted once)                        |
