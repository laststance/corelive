## Demand Evidence

- What he would scramble to replace first: 「LiveEditor の書いて Cmd+Enter で完了する一連」 — the write → Cmd+Enter → line becomes a Completed record loop. Not the heatmap, not Floating, not skill-tree.
- Second nameable user: none. 「自分だけ。具体名は出ない」.
- Corroboration from git: the last three months of commits (v0.20.x → v0.21.0) are almost entirely LiveEditor completion / clear / sound / shortcut fixes. The place being repaired is the place being used daily.

## Status Quo

Before CoreLive: 「メモ・テキストファイルに書いて消していた」. The cost was not time, it was the trace: nothing accumulated, so the day ended with no evidence of having done anything. The real competitor is a text file, not Things 3 or Todoist.

## Target User & Narrowest Wedge

- **User #1**: Raphtalia. Solo developer, writes-and-deletes, wants end-of-day self-affirmation without being graded (North Star: 「些細でも経験値、今日自分頑張ったなと自分を肯定できる感覚」).
- **User #2**: unnamed today. Chosen strategy (Approach C below): remove the login wall so a stranger can run the loop within 60 seconds of landing. This answers the Q4 bonus push "what if the user didn't have to do anything at all?" literally.
- **Wedge**: `corelive.app/live-editor` signed out. Write a line, press Cmd+Enter, the line is kept on the device, and a small ember under the editor says "3 things kept today". The footer link goes to `/login?redirect_url=/live-editor` (the login page already honors `redirect_url`; Clerk's login surface carries the sign-up link, and prod sign-up stays Turnstile-gated, which is fine for a human stranger). The link is framed as "keep it everywhere", never as "save".

## Constraints

- **Never grade, never shame** (DESIGN.md, non-deviable): no streaks, completion rates, KPI percentages, social comparison. Landscape evidence backs this: streak mechanics produce "streak creep", satisfaction drops after day 90, and users abandon rather than restart after a break.
- **Route gating today**: `src/proxy.ts` protects `/home`, `/skill-tree`, `/live-editor`, `/settings`. `/floating-navigator` is intentionally public and renders a signed-out front-door card (`FloatingNavigatorContainer.tsx` gates on `useUser().isLoaded` / `isSignedIn`) — the precedent for a public route with a signed-out state.
- **Packaged Electron panel contract**: the LiveEditor panel loads the remote `/live-editor` route and its ONLY signed-out signal is a navigation to `/login` or `/sign-up` (`AUTH_PATHNAMES`, `electron/WindowManager.ts` auth-redirect handling): on that redirect it hides the panel and falls back to the Floating OAuth front door. Installed builds have a frozen main process, so this contract must be preserved server-side in `src/proxy.ts` (see "Rules that hold everywhere"). A client-side redirect is too late: the panel's watchers stop at the first `did-finish-load`, which fires before Clerk's `isLoaded`, so `/login` would render inside the already-revealed panel. Real signed-out parity inside the panel needs a main-process release and is out of scope here.
- **Clerk readiness hooks**: `useClerkQueryReady` returns `false` while signed out; any signed-out render must gate on `useUser().isLoaded` / `isSignedIn` instead, or the page spins on "Loading…" forever.
- **Signed-in web `/live-editor` today** renders the "LiveEditor is available in the CoreLive desktop app" notice (`LiveEditor.tsx` desktop-only branch, reached from `AppSidebar.tsx`). The component is preload-bound: `activeCategoryId` waits on the preload `Promise.all`, the textarea is disabled until then, and notes load only through `api.note.get`. Giving the web a working editor is a host refactor, not a route edit.
- **Pre-launch freedom**: schema / API breaking changes are allowed (README). No migrations to preserve.
- **No-dedup principle**: repeating a task is a habit signal, never collapse identical titles. Accidental double submission still needs an idempotency key. The `ImportBatch` model exists in the schema but its write path was deleted in v0.21.0 (`157320ab`); nothing in `src/server` writes it today.
- **`createCompleted` has no `completedAt` input**: merged rows would all bucket on sign-in day (`completedAt ?? createdAt`). `Completed.categoryId` is required (`onDelete: Restrict`), so a merge must resolve the account's `Category.isDefault`.
- **Streak residue still ships**: `calculateStreaks` in `completed.ts`, `useStreakNotifications.ts`, `calc-streak.ts`, "longest streak" in `YearInReviewModal.tsx`, `AchievementAnimation.tsx`. Handled in Later.
- **Test infrastructure**: E2E / Playwright was removed in PR #167 (`2558b90f`); `pnpm validate` is vitest only. Any gate must name vitest suites or a `playwright-cli` recording.

## Premises

Agreed in session. #2 revised after the Codex cold read; #4 replaced by the Approach C choice.

1. The roadmap problem is the lack of a sorting criterion. The deliverable is one criterion plus a short Now / Next / Later list, not a new feature.
2. Core = the LiveEditor write → Cmd+Enter loop. **Reward = seeing "it was kept" right where you pressed.** The yearly heatmap is the long-horizon reward; its pull on daily use is unproven. **Criterion: does this make the daily loop faster, more reliable, or show the keep immediately?**
3. The promise is "a scratchpad that never forgets what you crossed out". Streaks, completion rates, and grading are permanently out of scope.
4. (revised) n = 1 today. User #2 is created by removing the login wall, not by handing a DMG to a named person. Onboarding beyond the signed-out page stays deferred until one named person has actually used it.
5. Anything that touches neither the loop nor the reward (skill-tree, more themes, more windows) is a deletion candidate, not a polish candidate. Continue the v0.21.0 core-only direction.

## Landscape (generalized web search, 2026-09-02)

- **Layer 1**: heatmaps are commodity in 2026 habit trackers (Habitify, HabitBox, Streaks) and are almost always paired with streaks.
- **Layer 2**: streaks backfire — "streak creep", day-90 satisfaction decline, abandon-after-break, dread replacing pride. "Done lists" are recommended for motivation; Todoist's "64% completed" made a reviewer feel like a failure. Done-list apps exist (MyDone) but are manual journals.
- **Layer 3 / eureka**: the category assumes fear-of-breaking-the-chain motivates; the evidence says the chain is the churn mechanism. CoreLive keeps only unbreakable accumulation: a bad day is an empty cell, not a failure. And because the write-and-delete user's pain is on the input side, the scratchpad → done-list pipe (Cmd+Enter) is the differentiator, not the heatmap.

Sources: The Decision Lab "Streak Creep"; Klarity "Why Streak Features Fail ADHD Users"; Yu-kai Chou "Streak Design: Motivation Without Burnout"; Medium "Keep To-Do lists aside, go with Done Lists"; XDA "I deleted my to-do list apps for a week"; HabitBox "Best Habit Tracker Apps 2026".

- **B) Loop / Reward / Trace ladder** (M / Med). One item per layer per cycle. Rejected as a framework (too much structure for n = 1); the three-word vocabulary is borrowed for `docs/ROADMAP.md`.

## Recommended Approach: C — no-login LiveEditor, with the ember inside it

Wireframe (signed-out state, two screens, today-only ember): `~/.gstack/projects/laststance-corelive/designs/sketch-signedout-liveeditor-20260902.png`.

### Rules that hold everywhere

- **Auth gate**: the page and the component gate on `useUser().isLoaded` / `isSignedIn` (Floating pattern), never on `useClerkQueryReady`, which is `false` while signed out.
- **Packaged-panel contract**: `src/proxy.ts` keeps `/live-editor` protected when the request's `user-agent` contains `Electron/` (the packaged panel and `electron:dev` both send Electron's default UA; nothing in `electron/` overrides it). The panel therefore still receives the server-side `/login` redirect, hides, and falls back to the Floating OAuth front door exactly as today. Zero Electron change; one matcher unit test covering both UAs; the signed-out mode is web-browser only in this cycle.
- **Route**: `createRouteMatcher` lists are static, so the split is: drop `/live-editor(.*)` from `isProtectedRoute`, add `isElectronOnlyRoute = createRouteMatcher(['/live-editor(.*)'])`, and gate in the middleware body on `req.headers.get('user-agent')?.includes('Electron/')`. Signed-out browser visitors never trigger server writes; everything is client-side until sign-in.
- **Signed-in web gets the editor**: the desktop-only notice is replaced by the same editor with server completions and device-local notes. Success criteria therefore say "packaged Electron signed-in path has no regression" (the ember is its one visible addition), not "web unchanged".

### Now — PR-1: `LiveEditorHost` adapter + signed-out web render + local store

1. Extract a `LiveEditorHost` interface from the preload calls the component makes today (note get / set, config-ready, last category, environment flag) with two implementations: `electronPreloadHost` (current behavior, byte-for-byte) and `webLocalHost` (device-local).
2. `webLocalHost` is used whenever `isLiveEditorEnvironment()` is false (web tab, signed in or out); never test `window.liveEditorAPI` directly, because pre-rename installs expose only `window.brainDumpAPI`. Completion writes go to the server when signed in, to the local store when signed out. `webLocalHost` focuses the textarea on ready, since today's autofocus is gated on `isLiveEditorEnvironment()`.
3. Signed-out defaults: **clear-on-complete ON** with the standard linger, applied as a `webLocalHost` override while signed out, not by flipping `DEFAULT_SETTINGS` (the persisted Redux slice is shared with Electron and defaults to OFF); one implicit category; the Electron-only chrome is omitted (Follow Spaces, opacity, ✕ close, the category `Select`).
4. Footer: "Kept on this device. Sign in to keep it everywhere." → `/login?redirect_url=/live-editor`. The footer never changes; the storage-unavailable state is shown by the ember (PR-2).

### Now — PR-2: `TodayEmber` + `useTodayKeeps()`

1. `src/components/live-editor/TodayEmber.tsx`, props `{ todayCount: number; storage: 'ok' | 'unavailable' }`. One warm cell colored by `getHeatmapIntensityFromCount(todayCount)` using `HEATMAP_LEVEL_TOKENS`, plus one line of copy. Copy variants, all of them: headline "Nothing kept yet today" / "1 thing kept today" / "N things kept today" / "Can't keep on this device — sign in" (storage unavailable: private mode or quota); sub-line "Finished lines gather here. They don't disappear." under the headline in every state except storage-unavailable. No counts of what is left, no week, no strip.
2. `useTodayKeeps()` switches source on `isSignedIn`: signed in → the `total` field of `completed.heatmap(days = 1)` via the existing oRPC query (the `data` array omits zero-count days, so `data[0]` is not "today"); signed out → the local store through `useSyncExternalStore` with a `null` server snapshot (pattern: `useSelectedCategory.ts`); `getSnapshot` returns the raw stored string, which is referentially stable, and the count is derived in `useMemo` keyed on that string, avoiding React's "getSnapshot should be cached" loop.
3. Updates after a successful Cmd+Enter in the same viewport, no navigation; reverts on undo and on save failure; double-fire safe.

### Now — record it

`docs/ROADMAP.md` with the criterion and this list; recreate the `idea` label; file PR-1 and PR-2 through `/spec`.

### Next — sign-in merge

- New procedure `completed.importLocal({ batchId, items: [{ title, completedAt }] })`: writes `ImportBatch` with `batchId` as the id (uniqueness is the idempotency check), creates `Completed` rows with the given `completedAt` in the account's `Category.isDefault`, never dedups repeated titles.
- Runs from a root-level provider after sign-in (not from the page, because `/sign-up` force-redirects to `/home`). After success, local items are tagged `mergedBatchId`; the ember excludes tagged items and a later merge skips them, so sign-out / sign-in on the same device never double counts.

### Later

- Watch one named person use the signed-out page (15 minutes, silent).
- Signed-out parity inside the packaged Electron panel (needs a main-process release).
- skill-tree keep / delete decided by the criterion.
- Streak residue sweep: delete `calculateStreaks`, `useStreakNotifications.ts`, `calc-streak.ts`, the "longest streak" line in `YearInReviewModal.tsx`, and the streak branch in `AchievementAnimation.tsx`, unless a piece is explicitly exempted as celebratory copy that never shows a broken chain.
- #120 drag-to-Completed stays Later; #53 AI labels and #124 modifier chords are cut unless the criterion changes.

### Local store spec (signed out)

- `localStorage` keys: `corelive.local-completions.v1` = `{ version: 1, items: [{ id, title, completedAt (ISO), mergedBatchId? }] }`; `corelive.local-note.v1` = `Record<string, string>` keyed by `categoryId`, with `'local'` as the key for the implicit signed-out category (same map shape as `electron/LiveEditorNoteStore.ts`). IndexedDB only if a year of one-line entries ever exceeds the quota (it will not).
- "Today" = items whose `completedAt` falls on the local calendar day (same keying as the server's local-day bucket); the ember re-derives at a midnight tick.
- Undo deletes the local record by `id` and decrements the ember.

### Test gate

- `src/components/live-editor/LiveEditor.test.tsx` gains a web-host suite (the current suite mocks `useClerkQueryReady → true` and stubs `window.liveEditorAPI`); new `TodayEmber.test.tsx` and `useTodayKeeps.test.ts`; `electron/__tests__/*` unchanged and green.
- The 60-second criterion is a `playwright-cli` recording against prod in a fresh profile, frames extracted and inspected.
- Packaged Electron QA: signed-in Cmd+Enter, offline save failure, undo, and the signed-out → Floating front-door fallback still firing.

### Ceiling and upgrade trigger (recorded because the choice was 6/10)

- Device-local storage can be lost when browser storage is cleared; no multi-device until the merge ships.
- Safari ITP purges script-writable storage, `localStorage` included, after 7 days without site interaction; a signed-out stranger returning in two weeks can lose the trace. The merge in Next is the upgrade path.
- Signed-out mode is web-browser only; the packaged panel keeps today's front-door fallback via the UA-gated server redirect.
- Upgrade when a second person actually uses the page (then merge + durability first), or when the panel needs signed-out parity (main-process release).

## Success Criteria

- A fresh-profile visitor to `corelive.app/live-editor` meets no login wall and has the editor focused within 2 seconds of first paint, measured by a `playwright-cli` recording on prod.
- A first line is written and completed within 60 seconds in that same recording.
- After Cmd+Enter the ember updates in the same viewport without navigation; a reload keeps the count; midnight rolls it to zero.
- Signing in later carries device-local completions into the account exactly once; a second sign-in on the same device does not duplicate.
- The packaged Electron LiveEditor signed-in path has no regression; its only visible change is the ember, one bounded row inside the compact frameless panel (`LiveEditor.test.tsx` + `electron/__tests__` green, packaged QA passed). The signed-out front-door fallback still fires.
- Raphtalia opens `/home` less often for the "did I do anything today" check (self-report after two weeks) — Codex's test in its cheap form.

## Distribution Plan

Web: existing Vercel pipeline, renderer-only, live on merge to `main`. Electron: no release for PR-1 / PR-2 (the packaged panel keeps the server-side `/login` redirect through the UA-gated matcher, so its behavior is unchanged); the Later panel-parity item is the first thing that would need one.
